# Skills Reference Map

Quick index of all Matt Pocock engineering skills, categorized.

## Foundation

| Skill | When to invoke |
|-------|---------------|
| `setup-matt-pocock-skills` | First time in a new repo — bootstraps issue tracker, triage labels, domain docs |
| `writing-great-skills` | Read when authoring or editing a skill (reference, not invoked) |

## Discovery & Research

| Skill | When to invoke |
|-------|---------------|
| `research` | Need facts from primary sources (docs, source code, specs) |
| `ubiquitous-language` | Need to extract a glossary from conversation |
| `domain-modeling` | Need to sharpen fuzzy domain terms or create an ADR |
| `codebase-design` | Need vocabulary for deep module design discussions |

## Design & Planning

| Skill | When to invoke |
|-------|---------------|
| `design-an-interface` | Want to explore interface alternatives with different constraints |
| `to-spec` | Ready to synthesize conversation into a PRD issue |
| `to-tickets` | Need to break a spec into vertical-slice tickets |
| `request-refactor-plan` | Want to plan a refactor as tiny commits |
| `wayfinder` | Need to plan huge work spanning multiple sessions |

## Critique

| Skill | When to invoke |
|-------|---------------|
| `grill-me` | Want a relentless interview to sharpen a plan or design |

| Skill | When to invoke |

## Every skill's shape

1. **Trigger** — situation that calls for it
2. **Context load** — what it reads to understand
3. **Procedure** — steps it follows
4. **Completion criteria** — what signals done

All Matt skills are **user-invoked** (you say when) unless noted.
