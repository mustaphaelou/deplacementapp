The Skills Landscape

You have about 35+ skills available. This lesson gives you a mental map of the whole terrain — how skills are organized, what pattern they follow, and which ones chain together naturally.

The shape of a skill

Every skill in the Matt Pocock system follows the same pattern. Learning this pattern once lets you understand any skill without reading its full SKILL.md:

  1. Trigger — a specific situation where you'd invoke it (e.g., "the user says diagnose/debug this")
  2. Context load — what the skill reads from the conversation or repo to understand the situation
  3. Procedure — the steps the skill follows (often using parallel sub-agents)
  4. Completion criteria — what signals the skill is done
Key insight: Skills are model-invoked (the agent decides when they match) or user-invoked (you explicitly ask). Most of the Matt skills are user-invoked — you steer.

How skills chain together

Skills are designed to compose. Here's a typical workflow that chains through several categories:

research → domain-modeling → grill-me → to-spec → to-tickets → implement → code-review → qa

  1. research — gather facts from primary sources
  2. domain-modeling — sharpen terminology, create ADRs
  3. grill-me — stress-test the approach before writing a spec
  4. to-spec — synthesize into a PRD issue
  5. to-tickets — break the PRD into vertical-slice tickets
  6. implement — build each ticket
  7. code-review — review what was built
  8. qa — file issues from testing

Other common chains:

  • Refactor: request-refactor-plan → grill-me → implement → code-review
  • Interface design: design-an-interface → grill-me → implement
  • Quick prototype: prototype → qa
  • Session handoff: handoff → (next session uses the handoff doc)
